# Sokqa Studio 運営リスク低減ガイドライン（規約＋設計原則）

作成: 2026-09-21 / 状態: ドラフト（法的助言の代わりにはなりません。最終確定前に専門家レビューを推奨）

本書の目的:
- Sokqa Studio の運営者が被る法的リスクを構造的に最小化するための**設計原則と規約条文案**をまとめる
- 実際の提供形態と、規約に書く責任・権利・運用を整合させる。**規約だけで責任をなくすことはできない**
- AI 生成教材特有の問題（出所不透明性・商標・ライセンス継承）への対応方針を明確にする

---

## 1. サービスの位置づけ（リスクを決める最上流の判断）

Sokqa Studio は教材作成を支援するが、「ツール」と呼ぶだけで責任が限定されるわけではない。生成、保存、アクセス提供、配布、販売の実態を分けて評価する。

- `packops` はR2への保存とmanifest URLの発行を行う。運営管理のストレージから第三者が取得できるなら、公開カタログがなくても保存・アクセス提供への関与がある。
- QRやURLを渡すことは、運営のサーバーから切り離したZIPの持ち出しと同じではない。
- カタログ・販売手数料の有無だけで責任の有無は決まらない。認識、管理、関与の程度など具体的事情による。
- ローカル運用でも外部AIへの送信・公開ストレージ設定は別問題。社内限定とするなら、規約だけでなく認証・認可・URLの公開範囲も確認する。
- 日本での情報流通プラットフォーム対処法（旧プロバイダ責任制限法）の適用や義務は提供形態・規模等に応じて確認する。全サービスに同じ義務があるとは断定しない。

## 2. AI 生成と著作権の前提知識

### 2.1 学習と生成・利用は別
- 情報解析等の非享受目的の利用で検討されるのは著作権法**第30条の4**。要件と例外があり、すべてのAI学習を無条件に適法化する条文ではない。
- 特定モデルがどの国でどの根拠により学習されたかは、このリポジトリから確認できない。API提供者の現行規約、入力データの取扱い、補償の有無・除外条件を別途確認する。
- 生成・利用段階の侵害判断は、既存著作物との類似性・依拠性などが問題になる。学習が許容されることと出力を配布できることは別である。

### 2.2 出力・出典について保証しないこと
- 「日本語なら逐語再現がほぼ起きない」「追加指示なしなら安全」という保証や確率評価には根拠がない。
- 事実・アイデア自体と、創作的な具体的表現は区別する。言い換えでも翻案等が問題になる場合があり、AI経由で利用条件が消えるわけではない。
- テーマだけの生成から、モデルの学習由来の出所を信頼できる一覧として復元できるとは限らない。
- 入力・取得した資料は記録できるが、入力した事実は「全出力の根拠」「利用許諾」「適法性」を証明しない。不明な場合は「参照元の記録なし」とし、「参考資料なし」と断定しない。
- AI生成物の著作物性は人の創作的寄与などによる。生成しただけで新たな著作権が必ずユーザーに発生するとは書かない。

### 2.3 利用目的・ライセンス
- 引用は**第32条**が中心で、出所明示は第48条等も確認する。第35条は一定の教育機関における利用の規定で、すべての学習教材・社内研修に適用されるものではない。
- 個人の私的使用（第30条）と社内利用は同じではない。会社資料にも第三者の著作物や秘密情報が含まれ得る。
- 無料なら許可不要、有料なら侵害という区分ではない。ただし非営利限定などのライセンス条件や販売に伴う消費者対応は有償利用で重要になる。
- 出典・AI利用・非公式の表示だけでは、無許諾利用を適法化できない。CC BY-SA等の継承範囲は、翻案・編集・集合物等の実態に応じて確認し、パック全体に当然及ぶとは断定しない。
- IPA等はサイト全体の一般規約と個別資料の利用条件を区別する。「使用料不要」は利用者による有料配布禁止と同義ではない。公式の留意点まで確認する。

## 3. 避けるべき説明・運用

| 避ける事項 | 理由 |
| --- | --- |
| 「ユーザー責任」「関与しない」と書けば運営は無責任と説明する | 規約は権利者等の第三者を当然には拘束せず、運営自身の責任も消さない |
| 「対策をしない方が安全」として確認や通知対応を避ける | 適切な予防・対応はリスク低減に役立つ。対策の存在だけで責任が増すとはいえない |
| チェック合格や帰属注記の追加を「公開可」の保証にする | 検査対象外・見逃し・利用条件の未確認が残る |
| 推測した出典・商標権者・許諾を自動追記する | 不正確な帰属や利用条件の見落としにつながる |
| 「故意かつ反復・大量の侵害だけ禁止」と限定する | 一度の無許諾利用等も問題になり得る。正当な逐語利用とは権限で区別する |
| チャット履歴を完全な監査証跡として扱う | 本人性・保存期間・完全性の担保は別途必要。秘密情報の過剰保存にも注意する |

## 4. リスク低減のための設計原則（構造で守る）

1. **今回の開発は現状維持**: audienceチェックボックス、出典の自動追記、追加生成ガードは導入しない。この決定は法的安全性の認定ではない。
2. **チャットで任意レビュー**: 機械検証・品質・法的所見を分け、根拠・未確認事項を示す。サイトの保存ゲートや既存品質処理は変更しない。
3. **社内資料の正当な逐語利用を維持**: 「そのまま使う」という指示だけでは拒否しない。利用権限・秘密保持・外部AIへの送信可否は別途確認する。
4. **規約と実態の整合**: 保存先、第三者がアクセスできる範囲、運営ができる停止措置を明記する。存在しないアクセス制御や監査機能を約束しない。
5. **一般提供前の確認**: 通知窓口、確認・停止手順、必要最小限の記録、データ保持期間、API提供者の条件を法務と確認する。今回の実装済み機能とは区別する。
6. **有料配布**: 一律禁止・一律安全のいずれとも扱わない。サービスとして許容する範囲と個別素材の利用条件を分けて規約で定める。

## 5. 規約（利用規約）の条文案

以下は「Sokqa Studio 利用規約」に組み込むべき条項の骨子です。**最終文言は専門家レビュー後に確定してください。**

### 第○条（サービスの内容）
> 本サービスはAIによる教材作成を支援します。保存、URL共有その他の提供範囲は、実際に提供する機能および別途の説明に従います。生成物の正確性や第三者の権利を侵害しないことを保証するものではありません。

### 第○条（入力資料・生成物の利用）
> ユーザーは、入力資料の利用、外部AIサービスへの送信、生成物の利用・配布・販売について、必要な権限と適用条件を確認するものとします。利用権限のある社内資料等の逐語利用を一律に禁止するものではありません。

> 本サービスは、第三者の権利をユーザーへ付与するものではなく、生成物に著作権その他の排他的権利が成立することを保証しません。

運営とユーザーの間の権利処理、サービス提供に必要な利用許諾の目的・範囲・期間は、API規約等との整合を確認して別途確定する。無条件の包括的権利取得を定めない。

### 第○条（禁止事項）
> 第三者の著作権、商標権、プライバシーその他の権利を侵害する行為、秘密保持義務等に反する入力・開示を禁止します。

故意・反復・大量だけに限定しない。個別の指示を機械的に止める実装とは別の規約上の義務である。ソフトウェア自体のMIT Licenseと矛盾する一律の改変・解析禁止は置かない。

### 第○条（生成内容の確認・表示）
> AI出力には不正確な内容や既存表現との類似が含まれる場合があります。配布・販売前に内容および適用される利用条件を確認し、必要な許諾・出所表示等を行ってください。

AI利用・非公式の表示を求める場合は、サービス方針として定めるものと法律上の義務を区別する。虚偽の公式認定を避ける。新たな自動追記機能を実装済みとは記載しない。

### 第○条（責任範囲）
> ユーザーは、自らの入力・利用行為に関する義務を負います。この規定は、適用法令上免除できない運営の責任を排除するものではありません。

「運営は一切責任を負わない」という全面免責は採用しない。消費者契約法第8条・第10条等、故意・重過失、損害賠償の上限・除外を法務レビューする。第三者からの請求が規約だけで消えるとは説明しない。

### 第○条（権利侵害等の申告への対応）
> 運営は申告内容を確認し、必要に応じてユーザーへの照会や、管理可能な範囲でアクセスの一時停止等を行います。法令上の義務と関係者の権利に配慮して対応します。

受付先、必要情報、緊急時の措置、再確認・異議申立て、記録の保持期間を公開前に定める。「規約に審査義務なしと書いたから何もしない」とは運用しない。

### その他の必須検討事項
- プライバシーポリシー: 外部AIへの送信先・目的・学習利用・保存期間、R2等の委託先、削除方法。
- 利用規約の提示・同意・改定通知: 今回、新たな生成時チェックボックスは作らないが、規約が契約に組み込まれる手続きは別途確認する。
- 有料サービス・販売: 取引上の役割、特定商取引法上の表示、返金、非営利限定素材の制約等。
- 準拠法・管轄: 日本法を基本案とし、運営所在地・対象地域・消費者保護の強行規定を踏まえ専門家と確定する。

## 6. サイト追加なし・チャットでの任意レビュー（確定方針）

- ユーザーの決定により、個人/社内/配布を選ぶチェックボックスは**導入しない**。
- 今回はサイトのUI・API・生成プロンプト・保存ゲート・既存チェックを変更しない。新しい配布制限・免責の自動追記も加えない。
- 利用条件は規約で整理する。ただし「規約だけで安全」「予防策は逆効果」という結論ではない。
- `.qoder/skills/pack-review/SKILL.md` により、チャットで教材本文・設問・権利上の確認事項・誤字脱字・音声誤読予測を任意レビューする。
- 機械検査は `python scripts/packops.py review <slug>`。ローカル読み取り専用・Gemini/TTS API/R2呼出しなし。Markdown/JSONを返し、意味理解・法的確認・試聴の未実施範囲を表示する。
- チャットレビューの所見は公開許可ではない。修正・配置・試聴・外部API実行は別途の明示依頼を要する。
